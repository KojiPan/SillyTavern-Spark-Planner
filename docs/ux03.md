# 0.8.0：统一 UI、创作阅读与运行诊断

## 设计规范与公共组件

长期规范为 [ui-design-guidelines.md](ui-design-guidelines.md)，插件根目录 `AGENTS.md` 强制 UI 开发前阅读；宿主工作区入口也已增加对应链接。旧实施记录保留历史背景，本规范和本文是当前界面与证据边界的依据。

- `ui.css` 集中定义主题变量、文字层级、间距、控件、列表、工具栏及窗口；`style.css` 只作为样式入口。普通字段、正文和条目使用正常字重，辅助状态弱化；不使用固定品牌配色。
- `text-tools.js` 将放大、清空和 Token 统计归为同一条文本工具栏，复用原有计数和触摸拖高，不重做 tokenizer。只读内容没有编辑控件或统计。
- `editor.js` 统一原生 Popup 壳、内容滚动、未保存保护、嵌套返回、选择区及父页面焦点/滚动恢复。
- `ui.js` 提供轻量更多菜单和安全 Markdown 阅读。复用酒馆的 Showdown 与 DOMPurify，禁止脚本、图片、任意样式及事件属性；没有宿主库时退化为原样纯文本。显示不展开宏或应用角色正则，复制始终使用原文。

## 窗口与滚动

| 类型 | 尺寸与布局 |
| --- | --- |
| 主面板、Skill/火花、分析模块、指导编辑、放大编辑、本轮选材、材料阅读、运行诊断 | 约可用视口 90%；标题和必要底栏固定，中间单一滚动 |
| 渠道编辑、组合配置、模型匹配规则、普通参数 | 内容自适应，最大约 90%；内容超出才滚动 |
| 分类、新建包、重命名、删除确认 | 短表单/酒馆原生确认窗口，不填充空白 |

视口高度和位置使用 `visualViewport`，响应软键盘引起的视口变化；真机软键盘仍需人工检查。各主页面独立保留滚动，但每页内部只有一个主滚动区，分类和模块不建立滚动井。textarea 仅在编辑时允许文本滚动，拖高只捕获手柄上的指针。

## 页面与入口调整

- 当前页直接阅读指导，标题行复制/编辑；编辑保留原始文本，保存为新草稿，取消不修改方案。没有有效 guidance 的 AI 输出不交付指导，手写无需标签。
- 仅在可靠确认的实际指导与草稿不同时，阅读组件才需要视图切换；本版本原生链路缺逐来源映射，因此正常显示预计指导，不把装配内容当作实际。
- 「全部注入材料」和「Planner 原始输出」默认折叠。材料阅读可指导优先、逐项/全部展开；复制全部仍按装配数组原顺序，既不添加 UI 标题，也不重排内容。
- 删除两个常驻注入预览按钮、选材折叠内层、每个已选标签的重复编辑按钮。标签仍可点读、长按/右键/F2 编辑，本轮选材改为大型工作窗口。
- 底部只突出当前主要操作，重规划、重生成、恢复/清空方案及本轮诊断收纳到更多菜单。原始输出只展示模型可见返回文本，有独立复制入口。
- 创作库把搜索/新增/更多放入同一工具栏；条目主体直接编辑，不再每行追加同功能编辑按钮。无启用条件时不重复显示“按情境判断”。分析模块正常状态为“默认版本 · 已生效”，排序/删除在模块操作菜单。
- 当前聊天组合可直接打开紧凑配置窗口；包复制、导出、重命名、删除及全局组合位于创作包管理窗口。保留全部原功能。
- 设置继续沿用 UX-02 分组目录、直接提示词编辑、渠道自动模型获取/手动回退和密钥库。模型标签列表直接进入编辑器，删除移至编辑器并确认。

搜索、浏览包、分类展开、页/子页签和滚动不随普通状态更新重置。列表和渠道/历史使用数据签名跳过无关重建；生成结束及模型/Token 更新不会重建正在编辑的子窗口。全局包组合尚未保存的勾选也不会被状态刷新清空。

## 最终请求的捕获边界

1. 旧 `generation.items` 是 P2 的世界书扫描前装配快照。它不可改名为已确认最终注入，也不重算旧历史。历史仍以原快照复用，界面明确标成装配。
2. Planner 的原有 `inspectPlannerRequest` 在原生 `CHAT_COMPLETION_SETTINGS_READY` 或 `ChatCompletionService.sendRequest` 前提供原请求对象引用；Generation 在 `GENERATE_AFTER_DATA` 登记执行记录，并在 Chat Completion 的 `CHAT_COMPLETION_SETTINGS_READY` 取得最终参数对象。Text Completion 使用其生成数据 Hook。
3. `request-observer.js` 包装当前 `fetch`，只观察受支持的酒馆生成路径及 POST 字符串正文。只有正文与所登记原生对象的最终 JSON 序列化完全一致时才关联到对应运行。它不匹配提示词片段，不给正文加标记，不修改参数、signal、返回 Promise 或响应流，不修改酒馆核心。
4. `run-evidence.js` 按明确白名单保留模型可见消息/文本、工具定义/格式及必要参数，排除 API 地址、密钥、secretId、认证头和自定义连接字段。复制请求保留角色和顺序，其他参数仅在诊断中按需看。
5. 请求次数表示已观察到的浏览器 → 酒馆请求尝试；HTTP 状态与生成完成是不同证据。服务器供应商转换、服务器内部重试和商业模型计费不可从浏览器推断。

**本版本无法可靠取得最终请求中每项素材的来源映射。** `WORLD_INFO_ACTIVATED` 只证明世界书阶段激活；最终消息可能合并、展开宏、转换或裁剪，并未携带逐素材标识。因此，诊断记录激活证据与完整最终请求，但各项始终显示“最终来源未确认”，常规材料显示“实际注入记录不可用”。不使用精确/模糊文本相似度代替来源证明，也不凭空猜测预算、触发或裁剪原因。

如其他扩展在序列化后重写正文，导致无法与所登记对象关联，或调用不在受支持的路径/正文类型内，同样显示未捕获，不保存为其他轮次的请求。关闭面板不清除执行状态，也不会停止请求；取消、切聊天和原有中断保护继续由 Workflow 控制。

## 诊断与保存边界

「本轮运行诊断」在当前页更多菜单及历史记录内，按概览、Planner 输入、响应与解析、Generation 注入、时间线组织。正常首页为阶段结论，不默认铺 JSON；完整原始输出、候选目录、模块和模型版本、原任务协议、最终请求、UTC 与运行标识分区查看。

新增观测记录按聊天、轮次、请求 ID 及原有回复/swipe 归属保存于历史，不更改原始输出、资产和历史装配。新的完整请求正文最多保留最近 5 份，单份最多 50 万 UTF-16 单元、总计最多 150 万；超大、已清理、尚未捕获分别标识。仅清理新增诊断正文，不删除历史、旧 Planner 快照、素材或用户 Prompt；原有历史保留上限继续有效。

时间线只记实际执行过的代码阶段和观测到的请求。清理项特指执行引用释放，不宣称证明服务端上下文或其他插件状态。未记录的旧历史显示未知，不回填虚构时间与调用次数。诊断不会调用模型。

## 验证与限制

使用独立 `work/spark-ux03-data`（1.18.0，8062）及 `work/spark-ux03-data-119`（1.19.1，8063），上游均为随机本地 Mock。

- 新 UI 任务路径：指导原文复制/编辑、选择与应用、真实触摸长按、302 条素材整体滑动、搜索与滚动保留、新建火花/模块、紧凑组合、生成中关面板及编辑、请求冻结；360/390/430/1200px。
- 请求证据逐项对照本地上游收到的 Planner 和 Generation 消息，验证没有为了诊断改变请求；单元检查凭据白名单、原 Promise/信号不变、历史保留边界及指导视图。
- UX-02 回归覆盖未保存渠道、模型列表成功/空/失败/不兼容、迟到竞争、模型保持、密钥复用/清理、当前表单测试和渠道切换/删除。
- 运行模式回归覆盖自动/审核/手动、审核关闭重开、手改指导、原生 continue/regenerate/swipe、失败重试、重新规划、选材不可用、取消与切聊天。
- guidance 专项覆盖无标签、一个/多个、未闭合、嵌套与下一轮无标签；核对上游请求、对应扫描、装配、材料阅读和复制一致，保留鼠标/触摸调整高度及放大编辑回归。

自动化模拟视口及可信触摸事件不等于真机验收。仍需人工检查手机软键盘、系统返回键、横竖屏安全区、常用主题对比和第三方扩展组合；真实供应商、群聊工具循环及服务端转换没有全矩阵验证。所有验证不使用用户真实付费 API。
