# 0.6.0 多创作包与跨包迁移（2026-11-25）

本次检查了 Worldbook 的文件存储/事务、条目版本字段、ECoT 父子 UID、聊天历史及请求快照。沿用一份绑定世界书，创作包是逻辑组织与选材范围；没有改写请求快照、渠道、Prompt 组装、模型匹配或酒馆核心。界面仍用原条目编辑弹窗，只增加所属包与随目标包联动的分类选择。

## 存储与升级

世界书根对象新增 `spark_planner`：

```json
{
  "packVersion": 1,
  "packs": [{"id":"default","name":"默认创作包","description":"","categories":["未分类"]}],
  "defaultEnabledPackIds": ["default"]
}
```

每个拥有的主条目在既有 `spark_planner` 元数据中增加 `packId`。包的条目集合由此关系取得，不维护另一份易失配的正文库。标题/包名均不参与身份判断；同名分类只在包内操作。模型标签和分析模块仍使用既有全局插件设置。

首次读取旧库或执行管理写入时，将全部旧主条目归入默认包，复制原 `settings.categories` 和实际分类。迁移只增加归属与注册表，不重写正文、版本、主/子 UID、原生插入设置、普通条目或聊天。原 settings.categories 保留作为旧数据。迁移幂等，未知注册表版本明确报错。

注册表、分类和条目归属沿用同一个 `Worldbook.mutate` 文件事务；写前检查缓存/磁盘、预览指纹、提交前变化、Web Locks 和 HTTP 响应。备份新增注册表，恢复继续只替换拥有条目及其注册表。原生服务器仍没有 CAS，跨客户端最后一次读与写之间的竞态边界不变。

## 启用与规划

全局默认组合保存在当前绑定库的根注册表，适用于此账户使用该库的所有聊天。当前聊天覆盖保存在 `chatMetadata.spark_planner.enabledPackIds`；缺少此字段时继承全局，空数组代表全关。新聊天继承全局；已有覆盖不随全局调整而变化。可以从设置显式恢复继承。切聊天直接读取该聊天元数据，不复制上个聊天的组合。

总开关 → 包启用 → 条目设置层可选 → 原主模型版本解析 → 原候选规则。所有通过的包合并后统一动态编号；Reasoning 上限保持原配置，火花合计三项。点选区默认跨启用包搜索，已被关闭包中的原选项仍显示不可用原因，不能手选绕过。

本轮正文/模型版本内容仍遵循既有快照，但每次 activation 重新读取主条目的当前归属、可选状态、存在性与包组合。移动后不能用历史 `packId` 绕过关闭；条目已删除也不能继续注入旧快照。历史原始选择、原始响应、请求及 applied 快照不会被迁移重算。当前页诊断显示包关闭、删除或模型不匹配；历史回用保留原选择，不自动开包。

## 编辑、世界书与导入

库顶部浏览包与包启用互相独立，分类/搜索/紧凑行仅展示当前包。设置提供创建、名称/描述、复制、删除、单包 ZIP 导出、ZIP/Markdown 新包导入和全局组合。复制明确产生新包 ID 与新条目 ID；移动保留原条目 ID。

编辑选中其他目标包时，分类下拉立即换为目标分类，允许弹窗新建目标分类；新分类随条目保存提交，取消不写入。保存仍用原 `upsert`，不创建重复主条目，也不搬运至另一世界书。全部版本、插入设置和 ECoT 同源关联保留，父子 UID 不变。迁入当前聊天未启用包时成功反馈说明本轮/后续生成会跳过。

ZIP v3 manifest 和每个 Markdown frontmatter 带白名单包元数据，保留全部版本/推荐/正文、native 参数和引用标签。无默认版时仍完整导出专用版。继续读 v1/v2 和旧 Markdown，新包导入不默默覆盖旧条目。包 ID 或条目 ID 冲突在确认预览中明确列出新 ID；标题相同不合并。包名可相同，身份由 ID 区分。已删除的包 ID 留在注册表 `retiredPackIds`，再次导入也重分配，避免其他聊天的旧覆盖把新包自动启用。

导入/复制/创建不会加入默认组合或当前覆盖。标签冲突仍走原 `mergeImportedTags`，不另建包内匹配库。导出不含世界书 UID、渠道、API Key、聊天或规划历史。低层 `importSkills` 继续保留原稳定 ID 更新接口供内部兼容；新包 UI 总是使用不覆盖的确认路径。

## 兼容边界

- 老历史缺少包字段时通过当前稳定条目 ID 找真实归属，原请求快照保持原数据；没有请求的旧记录仍不重建请求。
- 与旧版不同：已删除的无 ECoT 条目也会明确不可用，以符合本次历史恢复要求；历史内容仍可查看。
- 老版插件无法正确维护包注册表/归属。降级前应导出完整绑定世界书；不要同时用旧版插件编辑已迁移库。
- 多包共用一个世界书，不支持每个包独立绑定世界书；不改变现有原生世界书预算、触发率、Outlet 宏和高级过滤语义。
- 跨客户端并发边界、所有真实 Provider、群聊工具续轮与真实手机软键盘仍需按原兼容说明检查。实际测试证据见 [TESTING.md](../TESTING.md)。

## 分析模块扩展

创作包还可包含独立分析模块，存于包注册表的 `analysisModules`，不进入普通条目分类。包复制/导入/导出/删除会一并处理模块；移动模块保留其身份与所有版本。ZIP v3 的 manifest 增加可选模块列表，格式标记和已有字段不变。模型标签与旧版本规则共用。详见 [分析模块](analysis-modules.md)。
