# Planner 分析模块

> 当前入口为“创作库 → 分析模块”。所有模块统一只交付完整 guidance 标签内文本，旧注入模式字段不再参与运行。下面的旧阶段行为以 [指导与预览修复记录](guidance-preview-fix.md) 为准。

设置 → Planner 分析模块统一管理所有创作包中的模块。每个模块有名称、可选描述、所属创作包、启用状态、稳定 ID、默认排序与模型版本；每个版本独立保存分析资料和输出格式。管理页不展开长文本，编辑弹窗沿用条目编辑器的独立滚动、固定关闭/保存操作、放大编辑、草稿与错误反馈。

模块由用户手动启用。只有创作包在当前聊天启用、模块自身启用且模型版本适用时，模块才进入 Planner。模型匹配直接复用 `resolveVersion`，匹配的是 Generation 主模型，允许默认版和多个专用版；没有匹配且没有默认版则跳过。模块不参与 Reasoning Skill 或火花的选择名额，也不进入普通条目的分类或候选目录。

## 存储与创作包生命周期

- 模块存于绑定世界书的 `spark_planner.analysisModules`，通过现有世界书事务保存、备份与恢复；不创建额外世界书条目。
- 模块启用状态沿用原全局模块设置的归属，持久化在模块上。聊天排序存于已有聊天 Planner 配置的 `analysisModuleOrder`；新聊天按模块 `order` 排序。换包不更改模块启用状态或聊天排序。
- 编辑时更改所属创作包即移动，保留 ID、全部版本、启用及排序。目标包未启用时，弹窗和保存反馈都会说明暂不参与 Planner。
- 创作包 ZIP 的原格式标记和 v3 协议保持不变，manifest 增加可选 `analysisModules` 内容，并携带模块引用的共享模型标签。旧的无模块包继续可导入。包含模块的包应使用支持本功能的插件版本导入，旧插件会忽略新增字段。
- 包复制使用新包/条目/模块 ID；导入冲突沿用现有预览和新 ID 策略，标签冲突复用原重映射逻辑。包删除在同一事务中清理所属模块。包内只有模块时也可以导入导出。
- 历史、请求快照和迁移备份不随创作包导出。

## 五段提示词

1. 全局总任务。
2. Reasoning Skill 与火花的说明、动态编号目录。
3. 全局分析调度说明，以及 `analysis_modules` 中的各模块完整分析资料。
4. 全局输出总协议。
5. Reasoning Skill / 火花选择标记、分析模块输出总起，以及 `analysis_module_formats` 中的各模块完整输出格式。

两处容器使用同一批有效模块、同一顺序和从 1 开始的本轮编号。不会在提示词里暴露模块数据库 ID 或创作包内部 ID。模块名称和正文中的 XML 特殊字符会转义；Markdown 标题、编号和换行保持。XML 标签用于资料边界，最终分析正文不必复现。

全局总任务、目录前后说明、调度说明、输出协议、选择标记和分析输出总起都可以在任务提示词设置中独立编辑。全部模块关闭时不装配模块容器，选择标记和两个条目目录仍可使用。两个上下文模式、独立/继承渠道及最终 User 层任务装配方式不变。

## 旧心理发现迁移

首次在绑定世界书读取模块时，将旧 `settings.analysisModules` 原有模块或单一 `prompts.discovery` 迁到默认创作包。模型版本、资料、格式、ID 和启用状态保留；空模块数组表示用户原本关闭所有模块，不自动补回心理发现。

已知旧默认混合协议通过完全相等判断拆分：心理发现格式移到模块版本中，全局协议改为统一规则。自定义总任务和目录文字保持原样。自定义输出协议不通过关键词猜测切分，而是原样继续兼容，并在设置中显示“检查旧协议迁移”：用户先在相应模块保存格式，再编辑全局协议并确认。确认前，旧自定义协议可能继续要求心理发现，即便模块已关闭；界面明确提示此兼容限制。

原全局提示词保存在 `analysisPromptBackup`，原全局模块字段也保留作迁移来源，迁移后不会从这些旧字段再次加载内容。世界书迁移标记与模块数据一同提交，设置记录迁入世界书，避免刷新重迁、切换世界书后重复复制。保存失败不确认迁移；旧历史和实际请求均不重算。

## 结果与快照

Reasoning Skill 与火花继续使用原选择标记解析。各模块可配置全文注入、标签提取或仅供查看；旧模块默认全文注入，新建模块默认提取 `<guidance>`。按模块标题边界分别处理后，合并为本轮创作指导，复用原镜像插入位置。缺失、空白或不完整标签不回退全文；混合模式下无法归属的文本也不交付。全部旧式全文模块仍保留无标题兼容。原始输出独立只读保存，人工修改创作指导不会改写它。完整运行控制与协议规则见 [P1 本轮规划](round-control.md)。

请求快照继续在原发送边界冻结。模块列表包含顺序、包 ID/名称、适用状态与原因、实际版本、完整资料和格式；结构视图显示每段全局来源、模块来源与本轮编号。最终消息数组保存真实发送内容，后续修改、移动或删除模块不会改变历史请求。

## 验证入口

`npm test` 覆盖模块版本、三重启用门槛、编号/边界、迁移、包生命周期、失败事务、自然语言空结果过滤和不可变快照。`npm run test:analysis` 只对可丢弃的本地官方宿主运行，使用本地模拟模型响应，覆盖手机编辑、放大与版本草稿、保存失败、跨包移动、实际请求、Generation、Swipe/Regenerate 和短视口布局。真实手机软键盘、主题与模型创作质量仍需人工检查。
