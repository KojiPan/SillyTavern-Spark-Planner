# 指导提取、注入预览与文本编辑专项修复

> 历史实施记录：0.8.0 的阅读入口、窗口策略及“装配/实际请求”证据边界以 [UI 与诊断实施说明](ux03.md) 和 [UI/UX 设计规范](ui-design-guidelines.md) 为准。旧文中的“实际装配”指装配快照，不代表已确认最终逐素材注入。

本记录覆盖此前 P1/P2 关于三种模块注入方式、旧模块全文兼容、预览格式和文本统计的设计。保留资产结构、世界书插入规则、模型匹配、运行模式和历史复用。不提交或推送 Git，不调用真实模型。

## 链路和问题根因

实际链路是 `Workflow.plan → parsePlanner → draft.discovery → apply/ensureDiscovery → activation → overlayLore → WORLDINFO_ENTRIES_LOADED → 原生世界书扫描/请求`。

旧版解析器存在两个真实请求问题：`full` 模块会交付整段结果；全部为旧式全文模块且没有匹配模块标题时，会回退整段分析。这些文本写入 `discovery` 后确实会被作为指导交给 Generation，并非只存在于预览中。

世界书 JSON 则是另一类 UI 问题。旧 `injectionText` 把范围说明、版本/配置和正文拼成一段，只供预览与复制使用；实际 `overlayLore` 使用 `entry.content`，没有调用这个格式化函数。**配置 JSON 和预览说明此前只混入预览/复制，没有由插件装配链路作为创作正文注入 Generation。** 旧版逐项装配 Token 统计本来只计正文，但通用预览 textarea 又对这段混合文本和说明进行了额外统计，造成范围混淆。

预览现仍由 `Workflow.previewInjection → resolveEntries → assembleInjection/overlayLore` 取得同一组正文；展示模块只读取这些 `items`。本轮实际装配入口读取请求边界保存的历史快照，不读取实时素材重建过去。

## 固定指导协议

所有 Planner 分析统一采用：

```text
<guidance>
实际交付给 Generation 的创作指导
</guidance>
```

`parsePlanner` 从完整可见 `raw` 提取所有有效完整标签，去掉外层标签，按出现顺序用空行组合。不依赖模块标题、顺序或旧 `injectionMode`。空标签、未闭合、带属性和非法嵌套块均不交付；无有效标签则为空，绝不回退全文。其他有效选材继续解析、去重和执行。

总输出协议运行时追加统一说明，用户存储的全局 Prompt、模块分析正文和自定义输出格式原样保留。旧 `injectionMode` 字段继续允许导入导出，但已没有运行控制作用，配置入口移除。诊断补充 `deliveryProtocol: guidance`，避免把保留的旧字段当作执行规则。

原始 Planner 输出独立保留在当前方案与历史记录。玩家填写或编辑的指导直接使用，不再要求标签。没有编辑过的旧 AI 草稿在首次读取时按原始输出重新提取，防止原生重生成继续使用旧版全文回退。已编辑指导、显式历史复用和历史快照属于用户确认的内容，不猜测改写；已保存历史保持原样。需要重做旧规划时可重新运行 Planner，执行新协议。

空指导应用会把指导镜像正文更新为空；扫描始终移除插件原扫描副本，且以当前 `plan.discovery` 覆盖指导，空正文不加入。本轮不会从上轮镜像补回指导。Skill、火花和既有附属 ECoT 的适配与原生插入字段不变。

## 预览与复制

新增 `injection-viewer.js`，仅复用原生模态壳，不再构造多文本框表单。

- 顶部显示预计/实际类型、Generation 模型和选材数量；范围说明是一行普通小字。
- Reasoning Skill、火花、创作指导分组阅读，显示标题、适配版本、System D0 等简洁位置、顺序与正文 Token。
- 正文使用 `pre` 的正常换行排版，统一随弹窗主体滚动，没有固定高度正文框或内部滚动区。
- 无指导显示“本轮无有效创作指导。”；因 Planner 缺少有效标签而为空时再显示对应说明。
- Token 分类和总计使用表格，不展示统计 JSON。完整世界书配置只在默认折叠的高级调试区按需生成，不参与正文统计。
- `injectionText` 现在只按真实装配数组顺序连接 `item.content`。复制不包含标题、范围、版本、内部 ID、配置、统计或其他 UI 文本。分组视觉顺序不会重排用于复制的装配顺序。

只读通用显示也改用普通文字；不再提供放大、输入框字数或 Token 统计。只读弹窗保留一个“返回”，去掉重复关闭入口；只读放大不再注册一个同名提交按钮。可编辑弹窗仍保留保存、取消和已有关闭行为。

## 文本框交互与 Token

新增 `text-resize.js`，共用右下角三角手柄、Pointer Events 和 `resize: vertical`。支持鼠标、触摸和方向键；只在手柄拖动时截获触控，正文和外层页面保持原滚动行为。解除原编辑器的固定最大高度，保留默认及最小高度。放大窗口同样可以拖动，外层编辑区可继续滚动，底部操作区保持可见。

高度偏好只存于本次页面会话内，按编辑器/字段区分；普通刷新、计数、版本切换、保存重开和放大返回不重置高度。没有写入 Skill、世界书或模型设置。关闭窗口释放 ResizeObserver。页面重新加载后的高度持久化不属于本次需求。

`text-stats.js` 统一显示右下对齐的 `Token：398` 或 `≈Token：398`。字符计数仅在内部估算使用，不再显示。保留 650ms 防抖、缓存和迟到结果隔离；统计不写 textarea 值、高度或光标。描述、模型匹配配置、说明与只读内容不统计。

宿主 `getTokenCountAsync` 可能静默使用代理 tokenizer 或估算，因此“返回数字”不视为准确证据。优先复用其计数；对本地明确支持的规范 OpenAI 模型，使用官方本地 encode 端点取得真实 token IDs 后才去掉约等于号。未知模型、代理/无法确认的模型或失败降级均保留估算标记，不调用模型供应商进行计数。计数仅指正文文本，不是消息包装、完整上下文或真实计费用量。

## 修改文件

- `core.js`：统一总协议、完整输出标签提取，移除全文回退。
- `workflow.js`：旧未编辑 AI 草稿的定向重提取、手动指导标记；原执行/扫描链路保留。
- `analysis-settings.js`、`analysis-modules.js`：移除模式选择 UI，保留旧字段兼容并标明实际协议。
- `injection.js`、新增 `injection-viewer.js`、`features.js`：正文复制、正文计数、普通只读预览及折叠配置。
- `editor.js`、新增 `text-resize.js`、`text-stats.js`、`index.js`、`style.css`：公共文本框交互/统计、只读展示和返回按钮。
- `request-viewer.js`：移除只读请求页的字符统计。
- README、测试和打包清单：更新被明确替代的旧行为断言；既有 fixture 需要有效指导时显式输出标签，不减弱运行隔离、错误恢复或请求冻结断言。
