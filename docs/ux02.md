# UX-02：历史、设置与 Planner 渠道

> 历史实施记录：0.8.0 的阅读入口、窗口策略及“装配/实际请求”证据边界以 [UI 与诊断实施说明](ux03.md) 和 [UI/UX 设计规范](ui-design-guidelines.md) 为准。旧文中的“实际装配”指装配快照，不代表已确认最终逐素材注入。

## 本次修改

- 历史按浏览器本地日期分组，显示本地时间、轮次、玩家输入摘要、选材计数和状态。摘要从已有记录和相同 turn 的玩家消息取得，不调用 AI。记录及运行详情默认折叠。
- 展开后展示实际素材标签和普通只读创作指导；实际注入继续使用 `injection-viewer.js`。原始输出、完整模型 ID、内部 ID、UTC 时间、版本及诊断集中在运行详情，保留实际请求查看与当前素材版本编辑入口。
- 统一「复用方案」入口，选择最新素材或历史快照。只有实际正文快照完整时才提供快照选项；缺快照的旧记录明确说明限制，不拿当前正文冒充历史正文。继续调用 P2 的 `flow.reuse`，不改变快照或重生成机制。
- 设置首页改为模型与运行、提示词与注入、高级设置三个分组。原有表单移到独立子页面，世界书绑定、资产来源提醒、原生编辑器、镜像修复、备份和诊断入口保留。
- 任务提示词在子页面直接展开编辑，修改自动保存；保留原名称、顺序、原文及恢复默认确认。复用统一 Token 统计、拖动高度和放大编辑组件。
- 渠道首页保留当前渠道选择器和继承主模型选项，以紧凑条目显示渠道名与模型 ID，点击整条编辑。新增渠道独立入口；测试、删除和保存集中在编辑器底部。

实现主要在 `index.js`、`features.js`、`channel-settings.js`、`model-list.js`、`settings-directory.js`、`history-view.js`、`channels.js` 和 `style.css`。`editor.js` 仅增加供确认删除后标记表单已处理的 `markClean` 回调。分发脚本包含新增运行模块。

## 模型列表的真实链路

1. 地址或 Key 输入变化立即使当前模型列表失效、取消当前浏览器请求；700ms 防抖后自动尝试查询。手动刷新使用同一流程。
2. 复用 `saveChannelKey` 和 `/api/secrets/read|write|rotate`。新 Key 先暂存在酒馆密钥库，用返回的 `secretId` 查询，不需要保存渠道配置。插件自己的密钥写入串行执行，写入后恢复主 Custom 连接此前激活的密钥。
3. 浏览器使用酒馆的请求头/CSRF 向 `/api/backends/chat-completions/status` 发 POST，参数为 `chat_completion_source: custom`、`custom_url`、`secret_id`。
4. 酒馆服务端按现有权限和密钥机制读取对应 Key，向该 API 根地址下的 `GET /models` 发请求。前端不直接访问供应商，不新增服务端接口，不发文本生成请求。
5. 前端仅规范化根地址末尾斜杠，不补 `/v1`。本地代理验收实际到达 `/a/v1/models`，没有重复路径。供应商模型 ID 原样保留，包括斜杠、括号和中文；搜索直接匹配真实 ID。
6. 成功列表仅在内存缓存 5 分钟，按渠道 ID、根地址及密钥引用区分。空结果、错误格式和失败有独立状态与手动输入回退。刷新不替换模型，当前模型缺席时保留并提示。
7. 每个编辑器维护请求版本；地址/认证编辑时立即失效，连密钥暂存阶段的迟到操作也要检查版本。旧响应不能回写新表单；关闭编辑器会取消请求和定时器。
8. 保存仅保留所需密钥引用，取消或关闭后删除本次编辑产生的其他临时密钥。原有已保存 Key 留空复用；地址改变时拒绝发送旧地址的 Key，必须重新填写。删除已保存渠道延续原行为，密钥仍留在酒馆密钥库。

真实 Key 只在输入控件、短期编辑器内存和酒馆密钥写入请求中流转。渠道配置、模型缓存、普通摘要、历史和创作包导出不包含 Key。测试结果将供应商错误映射为固定提示，不回显可能含凭据的错误正文。

## 参数继承与测试语义

| 配置 | 实际行为 |
| --- | --- |
| 继承酒馆主模型 | 继续走原有 `inheritedPlanner`；本次未修改该调用路径 |
| 最大输出 Token | 始终使用全局 `settings.maxTokens`，渠道编辑器只读显示继承值，不新增渠道覆盖字段 |
| 超时 | 已有渠道值优先；无值时使用全局 Planner 超时。编辑器沿用原保存语义，保存表单中的秒数 |
| 温度、思考强度、流式、排除参数 | 继续使用当前渠道字段，不改变请求适配架构 |
| Planner 上下文模式 | 继续使用全局 native/standalone 选择，与渠道选择分别配置 |
| 渠道测试 | 使用当前表单，经同一密钥库和 `ChatCompletionService` 调生成接口；短提示 `Reply OK.`、最大 64 Token。模型列表成功只表示列表接口可用，生成测试单独显示结果 |

测试按钮防重复；编辑配置使旧测试结果失效；只控制当前编辑器操作，不锁定规划器。服务端有时只返回 HTTP 状态文字，错误提示据其可用信息说明认证、路径/模型、限流或一般连接问题，不伪造供应商细节。

- `npm run check`：运行模块语法通过。
- `npm test`：111 项全部通过，含 P2 历史快照、最新素材复用、重生成及请求/注入回归，以及新增模型列表和错误脱敏测试。
- `node tests/ux02.e2e.mjs`：独立数据目录、真实酒馆服务端、随机本地 HTTP Mock。覆盖未保存渠道自动获取/生成测试、222 个模型搜索、完整 ID、刷新保留原值、缓存、保留密钥、认证隔离、空/失败/错误格式、迟到响应、取消清理、切换/删除，以及历史和设置页面。
- UX-02 每次运行包含 10 次本地模型列表请求、3 次本地生成测试（未保存成功、保存后成功、无效模型失败），无用户付费 API 调用。360/390/430/900px 无横向溢出；已目视检查手机历史、设置目录及渠道编辑器截图。
- `ST_TEST_URL=http://127.0.0.1:8052` 配合 `ST_TEST_LABEL=ux02-regression` 运行既有 `tests/guidance-preview.e2e.mjs`：15 次本地模拟生成通过，覆盖继承主模型、指导解析、实际请求/注入快照/剪贴板一致、长文本读取、放大、鼠标与触控调整高度。

8052 为根目录 SillyTavern 1.18.0 的隔离测试宿主，数据在 `work/spark-ux02-data`；8053 为 `work/spark-reference/runtime` 中 SillyTavern 1.19.1 的隔离测试宿主，使用 `work/spark-ux02-data-119`。两个版本均已通过 UX-02 验收。验收脚本只允许本地 8052/8053；不要指向日常数据目录。截图及脱敏结果位于 `test-results/ux02/1.18.0/`、`test-results/ux02/1.19.1/`，既有注入回归结果在 `test-results/guidance-preview/ux02-regression/`。测试和个人数据不进入分发包。
