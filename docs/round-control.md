# P1 本轮规划控制与选择性注入

> 本文保留 P1 阶段记录。三种模块注入模式、全文兼容和统计展示现已由 [指导与预览专项修复](guidance-preview-fix.md) 的统一标签协议替代。

- `analysis-modules.js`、`analysis-settings.js`：模块注入方式的校验、编辑与冻结诊断。现有世界书保存和 ZIP 导入导出已调用同一校验器，无需重建存储格式。
- `core.js`：模块范围内解析指导标签，按模式合并交付文本，在输出格式中追加标签协议。
- `README.md`、本说明、`docs/analysis-modules.md`：行为与兼容说明。
- `tests/round-control.test.js`、`tests/round-control.e2e.mjs`：P1 验收；更新旧测试中被 P1 明确替代的行为预期。`tests/ux-p0.e2e.mjs` 明确设置自动模式进行 P0 回归。
- `package.json` 增加 `test:round` / `test:ux` 入口；`scripts/package.mjs` 补入 P0 已依赖的文本统计与标签操作模块。不生成新发布包，不更改版本，不提交或推送 Git。

本地 `tests/`、`docs/` 和测试结果延续仓库现有的忽略规则，仍可在工作区直接查看和运行。保留实施前已有的 P0 未提交改动。

## 实际调用流程

1. 自动规划：原生 `Generate` 提交玩家消息 → 原生成拦截器调用 Planner → 冻结目录解析 → 建立并应用草稿 → 装配注入快照 → 原始 Generate 继续发出正文请求。
2. 审核后生成：同一拦截器调用 Planner → 建立未应用草稿 → 在拦截器中等待 Promise。继续按钮校验聊天、消息、目标回复、角色关键字段与人设，应用最终草稿并释放等待；原始 Generate 从原位置继续。不会再次发送玩家消息，也不会另起 regenerate 模拟恢复。重新规划只替换草稿，保留等待中的原生操作。
3. 手动编排：直接建立草稿 → 应用到当前聊天的待用方案 → 玩家使用酒馆发送/生成 → 同一拦截器跳过 Planner，将方案绑定到该次生成并装配注入快照。支持无玩家消息时的原生生成、仅选材、仅指导和空方案。

“仅规划”沿用原来中止外层请求的能力；它与保留原始调用的审核暂停不同。手动模式隐藏 Planner 操作，并在调用入口阻止 Planner 请求。

## 草稿与已应用状态

继续使用 `selected.reasoning`、`selected.spark` 和 `discovery`（界面名称为本轮创作指导）。不另建一份同义指导字段。

聊天元数据的 `draft` 表示当前可编辑方案；已有 `plans[turn]` 保留最近一次应用的副本与原有重生成能力。新增的必要归属/生命周期字段包括 `source`、`chat`、`world`、`revision`、`applied`、`next`、`consumed`、`generationFailed`、`awaitingReview`。无玩家消息生成用 `standalone` 记录归属；不存在虚构玩家消息。

编辑立即更新草稿并置为未应用，不调用模型、不修改执行快照。原始输出、原始解析结果和请求快照独立保留。手动选择没有 AI 数量上限。应用期间发生编辑、取消或切换上下文时拒绝过期提交。Planner 请求期间人工修改草稿时，迟到结果不会覆盖人工修改。

未应用修改会阻止使用旧方案生成；审核继续会自动应用。手动应用只登记方案，之后由酒馆正常生成。完成后标记方案已使用并清除执行状态；新消息不继承上轮方案。用户显式 Swipe、重生成、续写和失败重试可沿用当前轮已确认方案，并重新读取最新素材版本。

## 模块协议与兼容

`injectionMode` 为 `full` / `guidance` / `view`。缺字段的旧配置及旧创作包按 `full` 处理；编辑器新建模块默认 `guidance`。保存、包复制、ZIP 导入导出使用现有模块对象与校验路径。

标签模式仅在实际装配的模块输出格式末尾追加：“分析与构思完成后，将需要交付给 Generation 的内容放入 <guidance> 标签中。仅标签内部的内容会提供给 Generation。”用户自定义分析正文、格式及全局 Prompt 原样保留，不增加思考步骤或篇幅要求。

确定性文本扫描按模块标题边界分段。同名模块可按声明编号/顺序区分；深层 Markdown 子标题仍属于当前模块。每个模块单独提取所有完整且非空的精确小写标签，去掉外层标签后按原顺序组合。缺失、未闭合、带属性、错误嵌套的对应标签块没有交付内容，绝不回退全文。单个模块为空不影响其他模块或选材。

混合注入方式时，无法归属到模块标题的文本不交付，避免把查看内容混进指导；全部都是旧式全文模块时，保留旧的无标题兼容回退。缺指导的标签模块在原始输出旁提示。原始输出使用 `textContent`，指导使用 textarea `value`，不作为 HTML 执行。

## 注入与清理

继续使用现有绑定世界书、禁用镜像、插入位置、模型适配及 ECoT 同步。应用会更新禁用的指导镜像并登记方案；实际 Generation 装配时读取最新可用条目，冻结为 `active`。审核/手动方案中的已删除、禁用或失去适配的条目会被移除并要求再次确认；自动模式的已有轮次重生成沿用原有逐项诊断/跳过行为并提示，不使用错误素材。

`overlayLore` 每次从扫描副本移除本插件已有内容，再加入本次执行快照，避免重复。指导由快照的 `discovery` 覆盖；空指导不加入。没有原生条目被永久开启。修改选择后重新应用不保留移除的条目；空方案不注入旧指导。

成功、失败、取消、停止和切换聊天都清除 `active`。失败保留已确认方案；重试重新装配镜像。原生 Regenerate 回滚前先记录失败状态，再保存并恢复旧回复与候选，避免恢复过程丢失可重试状态。已发出的请求与执行扫描不受后续素材或草稿编辑影响。

## 重要决定与限制

- 审核恢复依赖原生拦截器仍在等待。关闭面板不会取消；刷新页面或切换聊天不会恢复旧调用。保存的等待标记用于阻止将失效原操作悄悄转换成 regenerate，需从酒馆重新发起并重新审核。
- 修改输入框中的未提交文本时阻止继续，并提示先清空或取消重发；已经提交的消息、目标回复、角色关键字段或人设改变时拒绝旧恢复。
- 完整原生调用只保存在内存，不持久化回调或重建另一条生成链路。
- 沿用显式重生成/续写对当前轮方案的复用；后续新轮次不自动复用。不新增历史快照系统、跨包搜索、完整注入预览或 P2 架构改造。
